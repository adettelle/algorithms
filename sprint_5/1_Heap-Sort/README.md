# A. Пирамидальная сортировка

Ограничение времени	5 секунд
Ограничение памяти	256 Mb
Ввод	              стандартный ввод или input.txt
Вывод	              стандартный вывод или output.txt


**В данной задаче необходимо реализовать сортировку кучей. При этом кучу необходимо реализовать самостоятельно, использовать имеющиеся в языке реализации нельзя. Сначала рекомендуется решить задачи про просеивание вниз и вверх.**

Тимофей решил организовать соревнование по спортивному программированию, чтобы найти талантливых стажёров. Задачи подобраны, участники зарегистрированы, тесты написаны. Осталось придумать, как в конце соревнования будет определяться победитель.
Каждый участник имеет уникальный логин. Когда соревнование закончится, к нему будут привязаны два показателя: количество решённых задач Pi и размер штрафа Fi. 
Штраф начисляется за неудачные попытки и время, затраченное на задачу.
Тимофей решил сортировать таблицу результатов следующим образом: при сравнении двух участников выше будет идти тот, у которого решено больше задач. При равенстве числа решённых задач первым идёт участник с меньшим штрафом. Если же и штрафы совпадают, то первым будет тот, у которого логин идёт раньше в алфавитном (лексикографическом) порядке.

Необходимо реализовать алгоритм сортировки кучей (англ. Heapsort) для таблицы результатов.

Создавать новые вершины нельзя.

### Формат ввода

В первой строке задано число участников 1≤n≤100000.
В каждой из следующих n строк задана информация про одного из участников.
i-й участник описывается тремя параметрами:

- уникальным логином (строкой из маленьких латинских букв длиной не более 20)
- числом решённых задач Pi 
- штрафом Fi

Fi и Pi — целые числа, лежащие в диапазоне от 0 до 10^9.

### Формат вывода

Для отсортированного списка участников выведите по порядку их логины по одному в строке.

Она полностью удовлетворяет свойству max-heap:

gena > timofey и gena > gosha;
timofey > rita и timofey > alla;
у gosha потомков нет.

gosha оказался выше alla, хотя alla в итоговой сортировке должна идти раньше него. Но это нормально. Куча не обязана хранить элементы в отсортированном виде. Она гарантирует только одно свойство: каждый родитель не меньше своих потомков.

Отношение между элементами из разных ветвей (например, gosha и alla) никак не регламентируется. Поэтому такая структура кучи абсолютно корректна.

Сравниваем с родителем: gosha(2,90) < alla(4,100)

Меняем местами.

gena(1)     alla(2)

4. rita 2 90

Сравниваем с родителем: rita(2,90) < gena(6,1000)

Меняем местами.

        gosha(0)
       /        \
    rita(1)     alla(2)
    /
 gena(3)

5. timofey 4 80

          gosha
        /       \
     rita       alla
    /    \
 gena   timofey

Сравниваем с родителем: timofey(4,80) < rita(2,90) ?
Нет, поскольку сначала сравнивается количество задач: 2 < 4
Значит rita имеет больший приоритет, поэтому обмен не нужен.

Итоговая минимальная куча:

              gosha(0)
            /          \
       rita(1)        alla(2)
       /      \
   gena(3)  timofey(4)

Заметим, что alla располагается выше timofey, хотя при сравнении (4,80) < (4,100), то есть timofey имеет более высокий приоритет. Это нормально, поскольку элементы находятся в разных ветвях дерева. Min-heap гарантирует только отношение «родитель ≤ потомки», но никак не упорядочивает элементы между разными поддеревьями. Поэтому такая структура минимальной кучи абсолютно корректна.

Высота двоичной кучи равна высоте дерева, то есть log2 N, 
где N – количество элементов массива.
//             20(0)
//           /        \
//       15(1)         11(2)
//      /     \       /     \
//   6(3)     9(4)   7(5)   8(6)
//  /   \      /
// 1(7) 3(8) 5(9) 17(10)

Новый элемент добавляется на последнее место в массиве, то есть позицию с индексом heapSize: 17(10)

Возможно, что при этом будет нарушено основное свойство кучи, так как новый элемент может быть больше родителя. В таком случае следует «поднимать» новый элемент на один уровень (менять с вершиной-родителем) до тех пор, пока не будет соблюдено основное свойство кучи:

//             20(0)
//           /        \
//       15(1)         11(2)
//      /     \       /     \
//   6(3)     17(4)   7(5)   8(6)
//  /   \      /  \
// 1(7) 3(8) 5(9)  9(10)

//             20(0)
//           /        \
//       17(1)         11(2)
//      /     \       /     \
//   6(3)     15(4)   7(5)   8(6)
//  /   \      /  \
// 1(7) 3(8) 5(9)  9(10)

Иначе говоря, новый элемент «всплывает», «проталкивается» вверх, пока не займет свое место. Сложность алгоритма не превышает высоты двоичной кучи (так как количество «подъемов» не больше высоты дерева), то есть равна O(log2 N).
